## New components

Two new style-only resources — both keyed `Style`s, not new Ether types — documented in
[`design library handoff/getting-started.md`](../../design%20library%20handoff/getting-started.md) §5:

- **Tooltip** (`EtherTooltip`) — a keyed `Border` style: inverse surface, `body/s-regular` text,
  `MaxWidth` 240 baked into the style (the child `TextBlock`'s `body/s-regular` style and `TextWrapping="Wrap"` are consumer markup, not baked in). A static visual surface, not the
  WinUI `ToolTip`/`ToolTipService`.
- **Panel Tabs** (`EtherPanelTabs`/`EtherPanelTabSegment`) — reuses the `EtherSegmentedControl`/
  `EtherSegmentPanel`/`EtherSegmentRadioButton` skeleton with a different skin only: a translucent
  track and a near-black/near-white selected pill instead of the brand-blue one. Same
  selection/data contract as `EtherSegmentedControl`.

Shipped set is now **17 controls** (11 Controls + 2 Surfaces + 3 Navigation + 1 Data Display —
`samples/Ether.DesignSystem.Gallery/ComponentCatalog.cs`), up from 15.

## API changes

- `EtherIntelligenceButton` gained `LeftIcon`/`RightIcon` (`IconElement` slots), with a default
  sparkles `LeftIcon`.
- **BREAKING: `EtherProgressBar`/`EtherSteeringBar` removed the static `ValueContent` override**,
  replaced by `ValueFormat` (a composite format string, e.g. `"{0:0}%"`). The value label now
  always tracks the live `Value` — there is no longer a way to set a static string that desyncs
  from it. A consumer that set `ValueContent` on `preview.1`–`preview.6` must migrate to
  `ValueFormat`, or to a `ValueContentConverter` (`IValueConverter`) for full control, which takes
  precedence over `ValueFormat`. With neither set, the control formats `Value` as a percent of
  `[Minimum, Maximum]`, same as before.

## Bug fix

`EtherSegmentedControl.SelectedValue` set from a XAML attribute is no longer cleared before the
segments realize — previously this lost the initial selection. Caught by the out-of-repo
`scripts/Verify-ExternalConsumer.ps1` check, not the in-repo `ConsumerFixtures` harness (see
`docs/internal/consumability/_SUMMARY.md`).

## Consumability

A grounded re-audit of the 10 components touched this session (Segmented Control, Tooltip, Panel
Tabs, Masthead, Card, Intelligence Button, Input, Dropdown, Progress Bar, Steering Bar) found the
product surface consumer-ready, and the `ConsumerFixtures` harness was driven back to green
(`scripts/Verify-ConsumerFixtures.ps1`, unpackaged and packaged, x64). New contract gates
(`Verify-EtherTooltipContract.ps1`, `Verify-EtherPanelTabsContract.ps1`) were added and wired into
CI and `scripts/Gates.psd1` for the two new style-only resources. Details in
[`docs/internal/consumability/_SUMMARY.md`](../internal/consumability/_SUMMARY.md).

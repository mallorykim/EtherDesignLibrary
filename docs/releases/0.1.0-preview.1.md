# 0.1.0-preview.1 — packed locally, not published

Status: **hold**. Local `dotnet pack` works. Do **not** `nuget push` until the
control surface intended for the first public preview is complete enough to
avoid a rapid preview.2 / preview.3 churn.

Remaining publish setup (when that surface is accepted):

1. Re-run `.\scripts\Verify-RuntimeGates.ps1` on a Windows desktop.
2. `.\scripts\Pack-PreviewPackages.ps1` (writes `artifacts/packages/`, gitignored).
3. Choose a feed (GitHub Packages, Azure Artifacts, or nuget.org) and credentials.
4. `.\scripts\Pack-PreviewPackages.ps1 -Source <feed> [-ApiKey <key>]`
5. Point at least one **out-of-repo** consumer at that feed (the in-repo fixtures
   only prove a local `ether-local` restore).

First coordinated preview of `Ether.DesignSystem.Foundation` and
`Ether.DesignSystem.Controls`. Preview API can still change.

## What package consumption already proved (in-repo)

A separate WinUI 3 app with **only** `PackageReference` (no library
ProjectReference) restored `0.1.0-preview.1` from the local feed, merged
`DesignSystem.xaml`, and instantiated the migrated controls. That is the
consumer-fixture smoke window. It is equivalent to a third-party app **except**
the feed is a folder on this machine, not a public source.

- x64 unpackaged package-consumer runtime markers for the migrated controls,
  including RTL (`RightToLeft`) inheritance, in-process UIA (EtherDropdown
  `LayoutFallback`; other 12 UIA rects), 225% `ScaleTransform`, fixture
  `.resw` / `x:Uid`, artifact screenshots, and elapsed harness `< 20000ms`
- x64 packaged consumer **build** and unsigned MSIX **produce** (not install)
- arm64 Foundation/Controls **pack** and unpackaged fixture **compile** (not runtime)
- Gallery smoke Light/Dark 20/20 is a ProjectReference host, not package proof

## Still red (not a stable release, and not a reason to push this preview)

- Control breadth still growing; first public preview is held on purpose

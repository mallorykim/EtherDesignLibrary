# 0.1.0-preview.1 — packed locally, not published

Status: **hold**. Local `dotnet pack` works. Do **not** `nuget push` until the
control surface intended for the first public preview is complete enough to
avoid a rapid preview.2 / preview.3 churn.

Remaining publish setup (when that surface is accepted):

1. Re-run `.\scripts\Verify-RuntimeGates.ps1` on a Windows desktop.
2. `.\scripts\Pack-PreviewPackages.ps1` (writes `artifacts/packages/`, gitignored;
   pack-only - it cannot push, see below).
3. Choose a feed (GitHub Packages, Azure Artifacts, or nuget.org) and credentials.
4. `.\scripts\Publish-Internal.ps1 -Push -PackageOwner <owner>` (or `-Feed <url>`),
   with `$env:ETHER_PUBLISH_PAT` set beforehand. This is the **only** authorized
   publish entry point (R-03): it re-runs the full acceptance gate chain derived
   from `scripts/Gates.psd1`, packs, then pushes only after a typed version
   confirmation. `Pack-PreviewPackages.ps1` has no push capability of its own -
   there is no path to `nuget push` that skips the gate chain.
5. Point at least one **out-of-repo** consumer at that feed (the in-repo fixtures
   only prove a local `ether-local` restore).

First coordinated preview of `Ether.DesignSystem.Foundation` and
`Ether.DesignSystem.Controls`. Preview API can still change.

## What package consumption already proved (in-repo)

A separate WinUI 3 app with **only** `PackageReference` (no library
ProjectReference) restored `0.1.0-preview.1` from the local feed, merged
`DesignSystem.xaml`, and instantiated the migrated controls. That is the
consumer-fixture smoke window. It is equivalent to a third-party app **except**
the feed is a folder on this machine, not a public source.

- x64 unpackaged package-consumer runtime markers for the migrated controls,
  including RTL (`RightToLeft`) inheritance, in-process UIA (EtherDropdown
  `LayoutFallback`; other 12 UIA rects), 225% `ScaleTransform`, fixture
  `.resw` / `x:Uid`, artifact screenshots, and elapsed harness `< 20000ms`
- x64 packaged consumer **build** and unsigned MSIX **produce** (not install) —
  `Verify-MsixPackage.ps1` also now runs in hosted CI (`build.yml`), since MSIX
  produce with signing disabled needs no GUI or desktop session
- Gallery smoke Light/Dark 20/20 is a ProjectReference host, not package proof
- High Contrast semantic slash keys match Light/Dark (234); leaves are Windows `SystemColor*`
- A truly out-of-repo consumer project (`scripts/Verify-ExternalConsumer.ps1`,
  none of this repository's `Directory.Build.props`/`Directory.Packages.props`
  inherited) restores, builds, and runs x64 unpackaged against the public NuGet
  surface only
- 445 of 1,388 public writable properties carry per-property evidence: 270
  proven to visibly take effect (pixel/layout/visibility differences on a
  rendered, attached control), and 175 proven only as a DP round-trip
  (getter/setter invoked on an attached control without throwing; bitmap
  pixels unchanged); the remaining 943 are verified only as callable, not as
  taking effect — see package READMEs
- 26 golden-baseline Light/Dark screenshots (one pair per control, 13 controls)
  gate visual regressions on upgrade

## Still red (not a stable release, and not a reason to push this preview)

- Control breadth still growing; first public preview is held on purpose
- Accessibility Insights, Appium / out-of-process UIA
- Hosted CI does not launch WinUI (`build.yml` keeps `-SkipRuntimeSmoke`); MSIX
  produce is the one runtime-adjacent step hosted CI now does run (see above)
- MSIX **install/runtime** (unsigned produce only; no `Add-AppxPackage`)
- Any architecture other than x64. `Directory.Build.props` now declares only
  `x64`/`win-x64` (2026-08-30); it previously also declared x86/arm64, but
  neither was ever built or verified by any CI job or release gate.
  `scripts/Verify-Arm64Packages.ps1` still exists and still works, but is no
  longer chained from `Verify-RuntimeGates.ps1` — see the comment at the top
  of that script to re-enable both together if arm64 demand returns
- Unpackaged `StorageFile` host-root `ms-appx` resolution (0/3), recorded in
  the consumer marker
